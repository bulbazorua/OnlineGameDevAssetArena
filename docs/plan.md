# Asset Arena roadmap

**Checkpoint 6A is implemented:** [autonomous idle/walk](06b-autonomous-idle-walk.md). Each character has private AI state, a seeded wander tactic and a shared intent/action path. Public movement reaches both players and delayed audience.

**Checkpoint 6A.1 is implemented: [dedicated AI threads and debugger harness](06d-ai-debugger-harness.md).** Each creature has a separate native Odin worker, private copied inputs/state and a separate development-only Godot inspector. The harness records real idle/wander branches, intent and host outcome with a timeline, event stepping, spatial data and rotating journals. `make ai_debugger P1=archer P2=orc` opens it. Stepping replays recorded decisions while the battle continues; cognition spanning multiple ticks remains future work.

**Checkpoint 6A.2: [responsive inspection and recorded-match QA](06e-qa-replay-and-trace-browsing.md).** Visible-row log rendering and background parsing keep selection responsive; colored decision graphs branch downward. `make replay` opens the latest recorded world with pause/play, seeking and P1/P2 traces on one clock. This displays saved host states; deterministic re-simulation is a separate planned checkpoint. [Daily log cleanup](log-cleanup.md) prunes expired diagnostics and recordings while protecting active and pinned runs.

**Checkpoint 6B.1 passes Team Lead technical re-review: [focused and peripheral vision](06g-focused-and-peripheral-vision.md).** The [review](06i-vision-team-lead-review.md) closes the wall-boundary, supported-range and individual-lifecycle findings after independent full-suite, regression and graphical checks. Owner physical-input feedback remains outstanding. The implementation provides detailed focused sightings, anonymous coarse cues, private expiring visual memory and Observe/Face behavior through the shared action authority. The decision inspectors and recorded replay retain the evidence used. The [research review](scratch2/planning.md) supplies the longer-term learning background.

**Implemented, 6B.1.1: [dedicated live senses windows](06l-live-senses-windows.md).** Default development launches now open six windows: two clients, two decision debuggers and two senses inspectors. Each senses window shows current focused sightings and coarse peripheral cues, sampled pose and freshness. A later owner-requested Exploration memory tab shows private visited regions. Traces, logs and replay stay in existing tools. [Arena cones and separate sense filters](06k-arena-sense-overlay.md) remain available. Only vision is active; hearing, olfaction, tactile/terrain and pain have honest unavailable panels. Full `make check`, native six-window integration and graphical debugger/replay checks pass; independent review and physical-input acceptance remain with the owner.

**Implemented, 6B.1.2: [composite opponent search](06m-naturalistic-opponent-search.md).** Normal creatures now explore, investigate coarse cues, pursue focused sightings, and search a fixed last-known area using private decaying visit history and independent random streams. F6 enables persistent per-window search diagnostics; host-confirmed acquisition displays a replaceable CC0 pixel marker. Hearing, scent and advanced learning remain later checkpoints. Stationary Observe remains an explicit vision QA mode.

**Checkpoint 6B.2 passes Team Lead technical re-review: [olfactory trails](06n-olfactory-trails.md).** Anonymous human/orc ground scent feeds independently scheduled noses and private search. Both Olfaction pages show delivered readings and honest zone coverage; F8 exposes the separate host field with saved filters. The [review](06p-olfaction-team-lead-review.md) closes R1–R3 after unchanged regression probes, full `make check`, graphical integrations and actual historical-replay checks pass. Debugger memory and recording-duration limits remain documented; owner physical-input acceptance is pending. The [delegation](delegation.md) is closed, and the [coding-agent report](06o-olfaction-coding-agent-report.md) preserves the implementation handback.

**Server refactor candidate: READY FOR INDEPENDENT REVIEW.** The Odin server is split into `content`, `simulation` and the host package without behavior, wire or diagnostic changes; see [server architecture](codebase/server-architecture.md) and the [coding-agent report](server-refactor-coding-agent-report.md). Not accepted until the Team Lead's independent review.

The [trainer arena checkpoint](05a-trainers-and-summoning.md) adds trainer-controlled movement and a host-timed summon sequence for the selected gladiators. Protocol version 7 introduced separate trainer and gladiator entities.

The separate [Player1 trainer harness](05-player-harness.md) now validates all eight required player animation states, with its own import package and processed outputs. Trainer movement/summoning are implemented in 5B; advice-driven gladiator behavior follows later.

The working game now includes **checkpoint 4C: selectable Archer and Orc**, using independently processed art, calibrated bodies, idle/walk animation and development action labels. All five asset folders were audited; Lancer, Warrior and Monk still lack required animations. Gameplay combat states, damage, projectiles and strategic AI remain subsequent checkpoints. The default five-second audience delay remains.
